# AI-Group1 产品工作流示意图

> 本文档描述当前产品的主要使用闭环：用户登录后进入房间，由主持人完成配置，玩家提交回合决策，后端调用 AI 推演并通过 REST/WebSocket 返回结果，最后进入下一回合或保存结束。

## 一、核心产品闭环

```mermaid
flowchart TD
    Start([开始]) --> Login[登录 / 注册]
    Login -->|JWT 成功| Home[进入首页]
    Login -->|失败| LoginError[显示认证错误]
    LoginError --> Login

    Home --> Rooms[浏览或创建房间]
    Rooms --> Join[加入房间]
    Rooms --> HostSetup[主持人配置房间]
    Join --> Waiting[等待其他玩家]
    HostSetup --> Waiting
    Waiting -->|人数与配置满足条件| StartGame[创建 GameSession]
    Waiting -->|断线| Reconnect[WebSocket 重连]
    Reconnect --> Sync[重新加入房间并同步状态]
    Sync --> Waiting

    StartGame --> Decision[决策阶段]
    Decision --> Submit[玩家提交 action]
    Decision -->|超时 / 无决策| Recovery[恢复服务检查并执行兜底策略]
    Recovery --> Review
    Submit --> Review[主持人审阅与修正]
    Review -->|需要补充| Decision
    Review --> SubmitAI[提交本回合给 AI]

    SubmitAI --> Inference[异步 AI 推演]
    Inference -->|处理中| RedisState[Redis 记录任务状态]
    RedisState --> Inference
    Inference -->|成功| Result[生成推演结果]
    Inference -->|超时 / 失败| RecoveryResult[恢复、重试或降级结果]
    RecoveryResult --> Result

    Result --> Broadcast[写入数据并广播状态]
    Broadcast --> PlayerView[玩家查看叙事、状态和情报]
    PlayerView --> Extra{是否使用扩展能力?}
    Extra -->|交易| Trade[发起 / 响应交易]
    Extra -->|任务| Task[查看 / 更新任务进度]
    Extra -->|存档| Save[创建或读取存档]
    Extra -->|继续| NextRound[进入下一回合]
    Trade --> NextRound
    Task --> NextRound
    Save --> NextRound

    NextRound -->|仍有回合| Decision
    NextRound -->|结束| Finished[完成对局并保留历史 / 策略数据]
```

## 二、回合状态机

```mermaid
stateDiagram-v2
    [*] --> decision
    decision: 玩家决策
    review: 主持审阅
    inference: AI 推演
    result: 结果展示
    recovery: 异常恢复
    finished: 对局结束

    decision --> review: 提交决策
    decision --> recovery: 超时 / 缺失决策
    review --> decision: 返回补充或修改
    review --> inference: 提交给 AI
    inference --> result: 推演成功
    inference --> recovery: 超时 / 结果缺失 / 数据异常
    recovery --> result: 重试或生成兜底结果
    recovery --> decision: 回退到可继续状态
    result --> decision: 进入下一回合
    result --> finished: 达到结束条件
    finished --> [*]
```

## 三、决策到推演的跨层时序

```mermaid
sequenceDiagram
    participant Player as 玩家浏览器
    participant Host as 主持人浏览器
    participant API as Express API
    participant DB as PostgreSQL
    participant Cache as Redis
    participant AI as LLM Provider
    participant WS as Socket.io

    Player->>API: POST /api/game/:sessionId/decision
    API->>DB: 保存 PlayerAction
    API-->>Player: 返回提交结果
    API->>WS: 广播决策状态变化
    WS-->>Host: 更新主持人审阅面板

    Host->>API: POST /start-review
    API->>DB: 切换回合状态为 review
    API->>WS: 广播 review 状态
    WS-->>Player: 显示等待审阅

    Host->>API: POST /round/:round/submit-to-ai
    API->>DB: 固化本回合输入与配置
    API->>Cache: 写入 inference processing
    API->>AI: 发送 Prompt、规则和玩家决策
    AI-->>API: 返回叙事、状态与影响结果
    API->>DB: 保存结果、事件、历史和自动存档
    API->>Cache: 写入 inference result
    API->>WS: 广播 result / session update
    WS-->>Player: 展示推演结果
    WS-->>Host: 更新主持视图

    Player->>API: GET /inference-result
    API-->>Player: 返回可查询的推演结果
    Player->>API: POST /next
    API->>DB: 推进回合或结束会话
    API->>WS: 广播下一阶段
```

## 四、断线重连与状态恢复

```mermaid
flowchart LR
    Connected[WebSocket 已连接] --> Disconnect[连接断开]
    Disconnect --> Reconnect[Socket.io 自动重连]
    Reconnect --> Auth{JWT 鉴权成功?}
    Auth -->|否| Offline[显示离线状态，等待重新登录]
    Auth -->|是| Rejoin[发送 rejoin_rooms]
    Rejoin --> RoomState[Redis 恢复房间在线状态]
    RoomState --> SessionSync[发送 session_sync]
    SessionSync --> Version{客户端版本落后?}
    Version -->|否| Recovered[恢复到最新会话状态]
    Version -->|是| Delta[请求 get_session_deltas]
    Delta --> Apply[前端合并增量状态]
    Apply --> Recovered
    Recovered --> Connected
```

## 六、状态与数据落点

| 数据 | 主要落点 | 生命周期 |
| --- | --- | --- |
| 用户、房间、会话、决策、事件 | PostgreSQL / Prisma | 长期保存。 |
| 房间在线成员与实时状态 | Redis + Socket.io 房间 | 对局期间实时维护，断线时恢复。 |
| AI 推演任务与结果 | Redis + PostgreSQL | Redis 负责处理中状态和短期结果，PostgreSQL 保存最终业务结果。 |
| 自动存档与历史 | PostgreSQL | 推演完成后保存，支持后续查看和恢复。 |
| 登录态 | 浏览器 Zustand persist | 客户端持久化，过期后回到登录页。 |

## 七、当前运行前提

完整工作流至少需要：

1. Node.js `>= 18`。
2. PostgreSQL 运行在 `localhost:5432`，并完成 Prisma 迁移。
3. Redis 运行在 `localhost:6379`。
4. 前端开发服务运行在 `localhost:5173`，后端运行在 `localhost:3000`。
5. 若进行真实 AI 推演，还需要在主持配置中提供可用的 LLM Provider 地址和凭据。

Docker 只是项目当前推荐的 PostgreSQL/Redis 运行方式；它不是产品业务流程本身，但缺少数据库和 Redis 时，登录、房间、推演和恢复闭环不能完整运行。
